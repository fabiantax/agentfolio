how stars are synced

agentfolio · GitHub stars → event-sourced shard → snapshot cache → cited chat answers

the one-paragraph version

A POST /stars/sync (owner-authenticated) triggers StarsSyncService.SyncAsync, which pages through https://api.github.com/user/starred?per_page=100 using the Link: rel="next" header until exhausted. Every repo becomes a star_synced event plus a projected row in the tenant's SQLite shard (event append + projection in one transaction). After success, a full-fidelity JSON snapshot is written through to object storage (S3/garage) at tenants/{tid}/stars/snapshot.json — a fresh, non-empty snapshot short-circuits the next sync (default freshness 360 min) so the demo doesn't re-crawl GitHub on every request.

reliability properties

event-sourced core

Every sync appends star_synced events before projecting — the stars table is a replayable projection (RebuildAllAsync: truncate + deterministic replay). The event log never grows on unchanged rows.

per-page resilience

Measured live: a 1000+ page fetch over ~45 min will hit transient failures (HttpClient timeout at 46 min; truncated response at ~20 min). Each page retries in place with escalating backoff — a failure no longer discards the whole fetch.

snapshot = explicit cache

Only a fresh, non-empty snapshot skips GitHub. Absent, stale, or unreadable → fetch for real. ?force=1 bypasses the cache entirely.

idempotent diffing

Repos canonicalize by RepoId; identical rows count as unchanged and write nothing — re-running a sync converges without churn.

Known gap (issue #62, open): the sync runs inline in the HTTP request with the request's cancellation token. The full 57.6k-repo fetch takes 25–40 min — far beyond any HTTP client timeout — so a client disconnect (measured: 499 at 292 s and at 30 s) aborts the sync mid-flight. The fix shape is already proven elsewhere in the codebase (uploads): return 202 Accepted + background job + GET /stars/sync/status. Until then, full syncs need a client that holds the connection (40-min timeout).
Current demo state: the pipeline is live and green end-to-end — verified with a real docx upload and a cited chat answer; the stars count in the showcase fills the moment a full sync completes (#41), which is the next queued story after #62.
