# AgentFolio on k8s (Hetzner VM, k3s) — af-11 notes

Generated by `aspire publish -p kubernetes -o ./k8s-artifacts` (Aspire 13.5.3) from `src/AgentFolio.AppHost`.

## What Aspire generates vs. what we must add

Aspire emits a Helm chart (`k8s-artifacts/`) with a Deployment + Service per resource
(`api`, `k8s-dashboard` OTLP endpoint). It does **not** generate storage, TLS, secrets, or
replica policy — those are covered below.

## SQLite persistence

SQLite is single-writer. The API pod needs a PVC:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: agentfolio-sqlite
spec:
  accessModes: [ReadWriteOnce]   # local-path on k3s supports RWO only
  storageClassName: local-path   # k3s default provisioner on the Hetzner VM
  resources:
    requests:
      storage: 1Gi
```

Mount at the API's data dir (the path the API uses for its SQLite file). Because RWO +
local-path binds the pod to the VM's disk, keep the pod pinned (single replica, default
scheduler on a single-node k3s).

## Replicas

`replicas: 1` — hard requirement, not a starting point. SQLite cannot handle concurrent
writers; never scale the API deployment beyond 1. Add `PodDisruptionBudget` with
`maxUnavailable: 0` only if you accept the tradeoff; simplest is to leave it out.

## Ingress / TLS

Use k3s Traefik ingress + cert-manager (already installed on the Hetzner VM):

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: agentfolio
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
spec:
  tls:
    - hosts: [<domain>]
      secretName: agentfolio-tls
  rules:
    - host: <domain>
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api-service   # see k8s-artifacts/templates/api/service.yaml
                port: { number: 8080 }
```

`ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` is already set in the generated values.

## Images

Build via Gitea Actions and push to the Gitea registry at `<host>:3200`
(HTTP registry → add `insecure_skip_verify` / mirror config in k3s containerd as needed).
Set the image in `k8s-artifacts/values.yaml`:

```yaml
parameters:
  api:
    api_image: "<host>:3200/<org>/agentfolio-api:<tag>"
```

## Secrets

Inject via a k8s Secret and wire through the deployment env (extend the chart's
`deployment.yaml` / `values.yaml`):

- `AGENTFOLIO_PASSWORD_HASH` — Argon2 hash for the dashboard/API auth
- `INGEST_TOKEN` — bearer token for the ingest endpoint
- NIM keys (`NIM_API_KEY`, plus any per-provider keys) — NVIDIA NIM access

```bash
kubectl -n agentfolio create secret generic agentfolio-secrets \
  --from-literal=AGENTFOLIO_PASSWORD_HASH=... \
  --from-literal=INGEST_TOKEN=... \
  --from-literal=NIM_API_KEY=...
```

Reference with `secretKeyRef` in the api deployment template; never commit values.


## Object storage (s3-03): Garage replaces MinIO (2026-09-16)
MinIO community edition is dead (console stripped 2025-05, images stopped 2025-10, repo
archived 2026-02). Demo backend = Garage v2.3 (Rust, Deuxfleurs, AGPL — separate process,
no linking): single ~19MB static binary, `garage server --single-node`, S3 API :3900,
path-style (our AWSSDK.S3 ForcePathStyle=true already matches), admin :3903.

k3s deploy sketch:
  - StatefulSet: garagehq.deuxfleurs.fr/garage:v2.3.0 image, /var/lib/garage PVC
  - Env: GARAGE_RPC_SECRET, GARAGE_ADMIN_TOKEN (Secret)
  - Init (one-off job): garage layout assign <id> -c <cap>; garage bucket create agentfolio;
    garage key create agentfolio-api -> AGENTFOLIO_S3_ACCESS_KEY/SECRET_KEY
  - AGENTFOLIO_S3_ENDPOINT=http://garage:3900, AGENTFOLIO_S3_BUCKET=agentfolio
Expiry: Garage has NO server-side lifecycle rules — UploadExpiryEnforcer (15-min scan,
24h TTL) is the mechanism of record; the in-memory tracking table becomes a durability
gap on restart (known v1.1 limitation, hardening backlog).
Fallback if MinIO parity needed: Silo (pgsty/silo fork, console restored, CVE-2025-62506
patched) — drop-in image swap docker.io/pgsty/minio.
